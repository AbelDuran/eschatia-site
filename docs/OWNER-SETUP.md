# Запуск кабинета и назначение владельца

Вход — только через Discord. Логины и пароли сайта не создаются. Сейчас без серверных настроек публичный сайт работает на исходных материалах, а кабинет показывает сообщение о подготовке входа. Это не демонстрационная авторизация: без Discord и PostgreSQL войти нельзя.

## 1. Сервер и база данных

Нужен хостинг с работающим сервером Next.js (Node.js), например уже используемый хостинг проекта, и постоянная PostgreSQL-база. Статический экспорт и GitHub Pages для кабинета не подходят. GitHub хранит код, но не анкеты, обсуждения и сеансы.

Создайте отдельную PostgreSQL-базу. Включите резервные копии и TLS подключения. Не используйте базу тестового окружения для рабочих анкет. Рекомендуется отдельный пользователь базы с правами приложения; миграции выполняйте учётной записью, которой разрешено создавать таблицы.

## 2. Создайте приложение Discord

1. Откройте https://discord.com/developers/applications и создайте приложение для сайта.
2. В OAuth2 добавьте Redirect URI **точно** вида `https://ВАШ-ДОМЕН/auth/discord/callback`, без лишнего завершающего слеша.
3. Скопируйте Client ID и Client Secret. Секрет вводите только в защищённые серверные переменные хостинга; не присылайте его в чат и не коммитьте в Git.
4. Бот не нужен. Сайт запрашивает только `identify`: ID, имя и аватар. Почта, сообщения и список серверов не запрашиваются.
5. Для локальной разработки добавьте отдельный Redirect URI `http://localhost:3000/auth/discord/callback`. Лучше использовать отдельное Discord-приложение для разработки.

## 3. Как выдать себе владельца

1. В Discord откройте **Настройки пользователя → Расширенные → Режим разработчика**.
2. Откройте меню своего профиля и выберите **Копировать ID пользователя**. Нужен цифровой Discord ID, а не ник, ID сервера или приложения.
3. На хостинге задайте серверную переменную `OWNER_DISCORD_ID` этим ID.
4. Убедитесь, что ID принадлежит именно вашему аккаунту. Перезапустите приложение после изменения переменных.
5. Войдите на сайт через Discord. В кабинете появится статус **Владелец**, кнопка **Управление сайтом** и раздел **Команда проекта**.

Владелец определяется только этой серверной переменной при каждом запросе. Роль не назначается первому вошедшему и не доступна для изменения в форме сайта. Для передачи владения замените ID на хостинге и перезапустите приложение. Новый человек должен войти своим Discord. Прежний владелец возвращается к своей обычной роли в базе.

## 4. Переменные окружения

Список без действующих секретов находится в `.env.example`:

| Переменная | Значение |
|---|---|
| `APP_URL` | Основной адрес сайта, например `https://example.com`, без пути. В production обязателен HTTPS |
| `DATABASE_URL` | Строка подключения PostgreSQL от провайдера; для удалённой базы с TLS |
| `DISCORD_CLIENT_ID` | Client ID приложения Discord |
| `DISCORD_CLIENT_SECRET` | Client Secret приложения Discord |
| `OWNER_DISCORD_ID` | Ваш цифровой ID пользователя Discord |

На локальном компьютере скопируйте `.env.example` в `.env.local` и заполните значения. Файл `.env.local` игнорируется Git. На хостинге используйте его интерфейс серверных секретов. Не добавляйте к этим именам префикс `NEXT_PUBLIC_`.

## 5. Подготовьте таблицы и исходные материалы

Из корня проекта в окружении с настроенными переменными:

```text
npm ci
npm run db:migrate
npm run build
npm start
```

Миграция создаёт таблицы, переносит исходных персонажей, страны, расы, организации и три новости. Повторный запуск не перезаписывает отредактированные материалы. Миграции запускайте при развёртывании, а не при каждом запросе пользователя. Перед обновлением рабочей базы сделайте резервную копию.

## 6. Назначьте администратора

1. Человек один раз входит на сайт через Discord.
2. Вы заходите в **Управление сайтом → Команда проекта**.
3. Для подтверждения полномочий повторно входите через Discord. Подтверждение действует 10 минут.
4. Выбираете человека; сверяете имя и полный Discord ID.
5. Выбираете роль «Администратор», указываете причину и подтверждаете.

Для отзыва выберите «Участник». Все сеансы этого человека завершаются, и он входит заново с текущими правами. Назначение записывается в журнал. Администраторы не могут выдавать роли; доступ к GitHub, хостингу и самой базе им не предоставляется.

Включите двухфакторную защиту Discord владельца и администраторов. Повторная OAuth-авторизация сама по себе не гарантирует отдельный запрос второго фактора.

## 7. Материалы и персонажи

- **Новый материал** поддерживает новости, персонажей, страны, организации, расы и мировой архив. Сначала сохраняется черновик; публикация выполняется отдельно.
- У существующего материала изменение текста применяется после сохранения; есть предпросмотр и история предыдущих версий. Их можно скопировать обратно в редактор.
- Изображение задаётся путём уже загруженного файла из `public` либо публичной HTTPS-ссылкой. Загрузки файлов с устройства в этом редакторе пока нет. Закрытые документы и вложения нельзя размещать в `public`.
- Существующие страницы сначала сохраняют исходную индивидуальную вёрстку. После редактирования в кабинете материал отображается в общем шаблоне статьи, с тем же адресом. Дизайн исходного контента и данные редактора не смешиваются.
- Чтобы связать существующего персонажа с игроком, откройте его материал и заполните Discord ID владельца. Игрок должен сначала войти. База не позволит выдать ему второго действующего персонажа. Замороженный персонаж также занимает этот слот.
- Новые анкеты: черновик → отправка → обсуждение → одобрение/исправления/отклонение. Изменения опубликованного персонажа проходят отдельное рассмотрение.
- Автор и вся администрация видят закрытую тему анкеты после первой отправки. Для новых ответов обновите страницу. Показываются последние 200 сообщений и 20 отправленных версий. Уведомления об ответах администрации приходят в кабинет автора.
- Заморозка обозначается на главной и на странице персонажа. Она блокирует сохранение новых черновиков игроком. Снять её можно публикацией материала.
- Удаление требует ввода названия. Оно убирает материал из публичных страниц, каталогов, рекомендаций и метаданных. История и обсуждения остаются закрытыми для возможности восстановления; это мягкое удаление, не физическое стирание базы.
- Связанные страницы подбираются по стране, расе, организации и явным ссылкам редактора. Из персонажей своей страны выбирается случайный; закрытые и удалённые материалы не выдаются.

## 8. Музыка

`EmptyCity` автора yd, CC0. Источник и лицензия: `public/audio/LICENSE.md`. Пользователь включает музыку сам. Один проигрыватель находится в корневом layout и сохраняется при переходах через Next Link; звук и громкость регулируются снизу страницы. Внешний переход в Discord, закрытие вкладки или полная перезагрузка документа не могут сохранять непрерывное воспроизведение; после возврата браузер может потребовать нажатия для возобновления.

## 9. Проверка перед открытием

Автоматические проверки: `npm test`, `npm run build`. Тесты используют отдельную PostgreSQL-совместимую базу в памяти и не обращаются к рабочим данным.

На настоящем домене отдельно проверьте реальный OAuth: обычный вход, отказ в Discord, повторный вход владельца, выход со всех устройств. Затем вторым Discord-аккаунтом отправьте анкету, обсудите её с администратором, одобрите, заморозьте и восстановите. Проверьте, что третьему аккаунту ссылка на обсуждение недоступна. Реальный OAuth нельзя проверить без ваших Client ID/Secret и зарегистрированного домена.

В браузере хранятся только защищённая cookie сеанса и локальные предпочтения темы/музыки. В базе — хеши сеансов, Discord ID, профиль, материалы, заявки, обсуждения, уведомления и журнал. Discord access/refresh-токены не сохраняются. SQL-запросы параметризованы, операции изменения проверяют Origin и роль, HTML из анкет выводится как текст. Старые сеансы и временные OAuth-запросы удаляются при входах.

Не публикуйте приватные страницы через CDN с общим кешем. Для `account`, `admin`, `auth`, `api/portal` нужно сохранять динамическую обработку Next.js. Ограничение частоты запросов на вход дополнительно настройте на хостинге; внутри кабинета есть серверные ограничения мутаций и сообщений.
